# toolslim

**Measure and losslessly slim the tool / MCP schemas your agent re-sends on every turn, and prove nothing broke.**

An LLM API is stateless, so every request carries the full definition of every tool, used or not. toolslim measures that cost per tool, rewrites the schemas with deterministic rules, and checks each rewrite with bidirectional property-based tests. Every rule is checked that way, and the checks run on the real servers below.

> mcp-context-budget tells you you're fat; toolslim puts you on a diet, and proves nothing broke.

## Results on 16 public MCP servers

Lossless rules only, `o200k_base`. Generated by [`bench/run_bench.py`](bench/run_bench.py); full table and per-rule breakdown in [`bench/RESULTS.md`](bench/RESULTS.md).

| server | tools | before | after | saved |
|---|---:|---:|---:|---:|
| notion | 24 | 17,498 | 4,974 | 71.6% |
| docs-lookup (FastMCP + Pydantic) | 4 | 897 | 611 | 31.9% |
| git | 12 | 1,473 | 1,207 | 18.1% |
| everything | 13 | 1,718 | 1,522 | 11.4% |
| playwright | 25 | 4,411 | 3,913 | 11.3% |
| github (npm) | 26 | 3,546 | 3,151 | 11.1% |
| filesystem | 14 | 2,877 | 2,640 | 8.2% |
| *9 more* | 51 | 21,183 | 20,390 | 3.7% |
| **all 16** | **169** | **53,603** | **38,408** | **28.3%** |

Read this honestly: **the median server saves 8.2%** (range 0.7%–71.6%). Notion dominates the total because every one of its tools carries all of its shared OpenAPI `$defs`, used or not. Without Notion the saving is **7.4%**. Every server got smaller, and none of them accepts or rejects a different argument after slimming.

Claude's own tokenizer isn't in these numbers yet (no API key in the run). Add it with `ANTHROPIC_API_KEY=... python bench/run_bench.py --anthropic`.

## Quickstart

```bash
pip install "toolslim[mcp]"

toolslim measure --mcp "uvx mcp-server-git"           # tokens per tool
toolslim slim tools.json -o tools.slim.json             # rewrite + savings per rule
toolslim check tools.json --baseline token-baseline.json --max-increase 10%   # CI gate
toolslim rules                                          # what each rule does
```

`tools.json` can be MCP (`inputSchema`), Anthropic (`input_schema`), OpenAI chat (`{"type": "function", "function": {...}}`), OpenAI Responses, or a raw `tools/list` result. Output keeps the shape it came in, extra fields included.

### Python

```python
from toolslim import slim_tools

tools = slim_tools(tools)  # list[dict] -> list[dict], same wire shape, input untouched
```

### GitHub Action

```yaml
- uses: actions/checkout@v4
- uses: rakeshnitb23/toolslim@v0.1.0
  with:
    source: tools.json          # or  mcp: "python my_server.py"
    max-increase: "10%"
```

With no committed baseline, the Action computes one from the PR's base branch, fails the PR if tool tokens grew past the budget, and posts a sticky comment with the per-tool diff and how much `toolslim slim` would save.

## Rules

All on by default. "Lossless" means validation-equivalent: any argument the original schema accepts, the slimmed one accepts, and vice versa. Descriptions and titles are annotations, so the rules that touch them can't change validation.

| id | name | what it does |
|---|---|---|
| SL001 | redundant-title | Drop `title` when it repeats the property, `$defs` or tool name (`"user_id": {"title": "User Id"}`) |
| SL002 | anyof-to-type-array | `anyOf[{type: X}, {type: null}]` → `type: [X, "null"]`; also merges type-specific keywords and turns `Optional[Literal[...]]` into one `enum` with `null` |
| SL003 | drop-null-default | Remove `"default": null` on properties that aren't required |
| SL004 | inline-single-use-defs | Inline `$defs` used once; delete `$defs` used never (never touches recursive defs) |
| SL005 | description-whitespace | Dedent docstrings, collapse space runs and blank-line runs, unwrap `**bold**` |
| SL006 | echo-description | Drop a description that only restates the name (`user_id: "The user ID"`) |
| SL007 | stable-order | Sort tools by name, keywords canonically. ~0 tokens; keeps the prompt-cache prefix byte-stable |
| SL008 | drop-schema-dialect | Drop zod's `"$schema": "...draft-07..."` when the schema means the same in draft-07 and 2020-12 |

Run a subset with `-r SL001,SL004`, skip some with `-x stable-order`.

## How the rules are proven safe

[`toolslim/equivalence.py`](toolslim/equivalence.py) compares validation verdicts, not schema text:

1. Generate valid arguments from the **original** (hypothesis-jsonschema) and validate them against the **slim** schema.
2. Generate from the **slim** schema and validate against the **original**.
3. Mutate every instance at every depth (`null`, wrong types, huge numbers, 300-char strings, dropped and extra keys) and require both schemas to give the same verdict. This catches a slim schema that *rejects* something the original allowed.

Test runs cover every rule on hand-written fixtures and the full pipeline on every tool in `bench/snapshots/` (169 real tools). CI on `main` repeats this with 200 examples per direction and every mutant (`TOOLSLIM_EQUIV_THOROUGH=1`).

What it caught while building:

- **The naive rewrite** `anyOf[X, null]` → `X` rejects callers who send an explicit `null`. That's why SL002 emits `type: [X, "null"]`.
- **Dropping `$schema`** from a draft-07 schema that uses tuple-form `items` makes a 2020-12 validator crash, and next to a `$ref` it silently switches on sibling keywords draft-07 ignored. SL008 refuses both.
- **A walker bug**: tuple-form `items` wasn't traversed, so SL004 could have deleted a `$def` that was still referenced. Now a regression test.

## Caveats

- **Tokenizer.** tiktoken is exact for OpenAI models and an approximation for everyone else. `-t anthropic` uses Anthropic's free `count_tokens` endpoint for ground truth (subtracting the fixed tool-use system prompt). Providers re-render tool JSON internally, so toolslim removes *fields*, not whitespace.
- **Prompt caching** cuts the *price* of re-sent tools (cached reads bill at a fraction of input), but slimming still lowers cache-write and cache-miss cost, frees context window, and lowers latency on misses. SL007 exists so caching keeps working.
- **Lossless means validation-equivalent**, not "the model behaves identically". Removing a redundant title or an echo description shouldn't change behaviour, but if you have evals, run them.

## How it differs

| tool | measures | rewrites schemas | proves equivalence |
|---|:-:|:-:|:-:|
| toolslim | ✓ | ✓ (deterministic, lossless) | ✓ |
| mcp-context-budget | ✓ (grades, CI gate) | – | – |
| ContextTax (C#) | ✓ | – | – |
| Headroom / sqz / rtk | – | compress tool *outputs*, not definitions | – |
| LLMLingua-style compressors | – | lossy, model-based | – |
